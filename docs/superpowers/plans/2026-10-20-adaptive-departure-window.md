# Adaptive departure window and late-cost implementation plan

**Goal:** 按每组实际总主体数计算出发窗口，将新实验迟到单位成本改为 4，并在聊天展示端点计算。

**Architecture:** 纯参数/端点函数给新 Session 保存规则；建场按市场人数冻结候选窗口。结算、展示、LLM、RL 读取相同的版本化成本和候选集合。旧 Session 保留原参数。

**Tech Stack:** Python 3.10、oTree、Decimal、unittest、既有独立 Liu-REL 经验学习算法。

## Global constraints

- 用户最终确认：标准为08:00到达；候选出发窗口扣除6分钟固定行驶时间，实际结算也保留这6分钟。
- 排队、早到、迟到单位成本分别为 2、1、4；不改变报酬公式和排队算法。
- N 为每组真人 + LLM + RL，总人数建场后固定；不按每轮到场人数或当轮容量重算。
- 同人数 I0/I1 窗口一致，页面/服务端/Agent 合法选项一致。
- 原有未提交修改和历史数据必须保留；不部署、不提交 Git、不调用付费服务。
