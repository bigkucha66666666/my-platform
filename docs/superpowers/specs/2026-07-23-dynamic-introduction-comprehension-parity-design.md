# 动态瓶颈介绍页与规则测试页同步设计

## 目标

让 `dynamic_bottleneck_round` 的介绍页和正式实验前规则测试页，在视觉结构、信息层级和题目表达上与 `single_bottleneck` 保持一致。动态场景只保留服务率机制上的必要差异，不改变现有实验计算、收费、分组、超时恢复或结果反馈逻辑。

## 介绍页

- 复用单瓶颈介绍页的最后提醒、四步流程、单瓶颈路径示意、核心信息区、阅读确认和进入规则测试按钮。
- 路径示意继续使用“居住地 -> 单一瓶颈 -> 工作地”的表达。
- 固定服务率说明改为动态服务率说明：
  - 服务率由系统按轮确定；
  - 同一轮内所有参与者面对相同服务率；
  - 同一轮内服务率保持不变；
  - 展示所有候选服务率及其目标比例或抽取概率；
  - 根据 `capacity_reveal_timing` 说明真实服务率在选择前或选择后公布。
- 不在 `after_decision` 模式中泄露本轮真实服务率。
- 保留收费提示，但不在介绍页重复展开收费计算。

## 规则测试页

- 复用单瓶颈测试页的视觉样式、题目卡片、场景条件区、答案反馈和按钮交互。
- 共 4 道题：
  1. 排队成本计算；
  2. 早到成本计算；
  3. 给定明确服务率、同一分钟出发人数和固定行驶时间，计算共同等待时间与到达时间；
  4. 判断同一轮参与者是否面对相同服务率，并完成包含粗收费的最终选择成本计算。
- 参与者点击“检查答案”后显示逐题解释；无论是否全对，阅读解释后均可进入正式实验。
- 测试答案不新增数据库字段，不进入导出。

## 后端模板变量

- 介绍页继续提供候选服务率、比例标签、公布时点、目标到达时间、固定行驶时间和收费说明。
- 增加与单瓶颈模板结构对应的服务率公布说明字段，避免模板自行推断配置。
- 测试页按当前动态配置选择一个明确候选服务率，生成整数形式的同分钟排队示例。
- 第三题的错误选项必须互不相同，且正确答案由现有 `service_batch_wait_minutes()` 计算得到。

## 稳定性边界

- 不复制或依赖 `single_bottleneck` 的模型类和运行时状态。
- 两个动态模板独立保存在 `dynamic_bottleneck_round` 中。
- 不修改动态服务率序列、收费校准、成本公式、页面顺序和恢复机制。
- 不修改 `single_bottleneck`。

## 验证

- 模板契约测试确认动态介绍页包含单瓶颈同款结构和动态服务率说明。
- 模板契约测试确认测试页包含 4 道题、场景卡片、答案反馈及动态服务率题。
- 单元测试确认第三题示例由当前候选服务率计算，且结果为整数显示。
- 运行动态场景 2 人完整 bot 流程。
- 运行原单瓶颈 bot 回归。
