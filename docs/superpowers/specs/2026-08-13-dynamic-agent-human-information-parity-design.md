# 动态瓶颈人类与 Agent 信息一致性设计

## 目标

让人类参与者、DeepSeek Agent 和独立 RL Agent 在每轮决策前获得相同的实验环境信息。三类参与者可以使用不同的内部学习机制，但不得因读取后台完整历史或当前轮后台数据而获得信息优势。

## 统一公开反馈

每轮结果结算完成后，系统生成一份组级公开反馈快照。快照内容与参与者结果页一致：

- 本轮真实瓶颈服务率；
- 各出发时间的匿名选择人数；
- 各出发时间参与者的平均最终选择成本；
- 当前轮所有参与者的平均最终选择成本。

每个参与者或虚拟 Agent 另有自己的个人反馈：

- 自己选择的出发时间；
- 排队时间和实际到达时间；
- 早到时间、晚到时间和最终选择成本；
- 本轮收益及实际收费、奖励结果。

快照包含人类、DeepSeek Agent 和独立 RL Agent 的匿名聚合结果，不暴露身份、人格、Agent 类型或参与者代码。

## 信息时序与防泄漏

- 第 1 轮没有历史公开反馈。
- 第 N 轮决策只直接提供第 N-1 轮已经结算的公开反馈，不直接提供更早轮次的完整记录。
- 所有参与者提交本轮选择前，任何一方都不能读取当前轮其他人的选择。
- `capacity_reveal_timing='before_decision'` 时，三类参与者都能看到本轮真实服务率。
- `capacity_reveal_timing='after_decision'` 时，三类参与者决策前都不能看到本轮真实服务率，只能看到候选状态、公开概率和历史反馈。

## 代码结构

在 `dynamic_bottleneck_round/__init__.py` 中增加统一快照生成和读取 helper：

1. 结算后根据已写入的 Player 和虚拟参与者结果生成快照。
2. 快照按轮次保存在本组参考参与者的 `participant.vars` 中，不新增数据库字段。
3. `Results.vars_for_template()` 使用该快照生成群体图表数据。
4. `AgentChoiceSet.history` 只传入上一轮公开快照和上一轮自身结果，不再传入完整逐轮历史。
5. RL 从上一轮快照读取匿名人数分布和公开服务率；Q 值、转移计数和策略参数仍保存在独立内部状态中，但决策接口不接收更早轮次的原始记录。

为减少改动风险，结果页的视觉结构保持不变，仅将后端数据来源切换为统一快照。

## 决策机制边界

信息一致不代表算法输入形式完全相同：

- 人类通过上一轮结果页观察公开反馈，并依靠自身记忆形成跨轮判断。
- LLM 每轮只接收上一轮结构化公开快照和自己的上一轮结果，由模型即时推理；不向其提供完整历史记录或额外机器摘要。
- RL 每轮只接收上一轮相同公开反馈，但允许其通过 Q 值和服务率转移计数形成内部学习状态。

这些属于认知和算法机制差异，而不是环境信息差异。论文中应明确区分“相同可观察信息”和“不同内部学习机制”。

## 失败与兼容处理

- 如果上一轮快照缺失，Agent 只能使用现有公开规则，不得回读当前数据库结果或更早轮次完整记录临时补全。
- 已经运行的旧 Session 没有快照时，从下一次成功结算开始生成，不修改旧轮次数据。
- DeepSeek API 调用失败时，备用策略仍使用相同信息边界。
- 不改变成本、收费、排队、payoff、分组、超时和导出结算逻辑。

## 测试

- 同一轮的 LLM 与 RL 获得完全相同的上一轮公开反馈快照。
- 快照内容与结果页群体图表数据一致。
- 快照包含全部人类和虚拟参与者，但不包含身份或 Agent 类型。
- `after_decision` 决策上下文不包含本轮真实服务率。
- 第 N 轮上下文不包含第 N 轮其他参与者选择。
- 第 N 轮 LLM 和 RL 决策输入不包含第 1 至 N-2 轮的原始反馈记录。
- RL 仍能从统一快照更新匿名人数分布和 Q 值。
- DeepSeek、独立 RL、组合模式和原有 `single_bottleneck` 回归测试通过。

## 不在本次范围

- 不为人类增加完整历史查询页；页面仍只展示当前轮结果。
- 不改变 RL 算法、人格参数和探索策略。
- 不新增神经网络训练、外部 RL 服务或数据库模型字段。
