# 动态瓶颈 LLM 受限外部记忆设计

## 目标

为 `dynamic_bottleneck_round` 中的 DeepSeek Agent 增加跨轮受限记忆，使其能够像人类参与者一样逐步形成对瓶颈服务率规律的主观判断，同时避免获得后台完整历史、精确转移统计或当前轮其他参与者选择。

## 记忆边界

- 每个 LLM Agent 拥有独立记忆，不与其他 Agent 共享。
- 第 1 轮记忆为空。
- 第 N 轮决策前，LLM 只能获得：当前轮人类可见信息、上一轮公开反馈、上一轮自身结果和截至上一轮形成的受限记忆。
- 记忆只允许概括已经公开的服务率、匿名群体选择、公开成本和自身经验。
- 不保存逐轮原始记录、参与者身份、当前轮其他人的选择、后台真实转移矩阵或系统未公开参数。
- 默认最大长度为 400 个字符；超出部分由系统截断。

## 单次 API 协议

沿用现有一次决策调用，不新增独立的记忆 API 请求。LLM 返回：

```json
{
  "departure_slot": 6,
  "reason": "选择接近目标到达时间的时点",
  "memory_summary": "近期较高服务率有延续迹象，但证据仍有限；下一轮继续结合最新公开结果判断。"
}
```

`departure_slot` 仍按现有合法选项校验。`memory_summary` 必须是字符串，清除控制字符并限制长度；缺失或非法时不更新记忆，但合法的出发时间选择仍可继续使用。

## 更新时序

本轮 LLM 在作出选择时，只能基于上一轮已经公开的信息生成新的认知摘要。该摘要先随本轮 Agent 决策记录保存，并在下一轮作为 `limited_memory` 传入提示词。因此它不能包含本轮尚未公布的真实服务率或其他参与者结果。

本轮结算完成后，系统不额外调用 LLM。下一轮提示中同时提供刚完成轮次的公开快照和此前保存的受限记忆，LLM再据此修正判断。这种一轮滞后的更新方式避免增加 API 调用，也保持同时决策的信息边界。

## 存储与配置

- 记忆保存在参考参与者的 `participant.vars` 中，按 `agent_id` 独立存储，不新增数据库字段。
- 每条 Agent 决策记录保存本轮输入记忆和输出记忆，便于后台复核和导出。
- 新增 session config：
  - `api_agent_limited_memory_enabled=1`
  - `api_agent_limited_memory_max_chars=400`
- 关闭开关时，提示中不提供记忆，且不更新记忆，行为退回无状态 LLM。
- API、解析或备用算法失败时保留上一条有效记忆，不因异常清空。

## 提示词约束

系统提示明确要求：

1. 受限记忆是该虚拟参与者此前形成的主观印象，不保证正确；
2. 只能根据当前提供的公开信息修正它；
3. 不得声称观察到上下文中不存在的数据；
4. 输出短摘要而不是逐轮流水账；
5. 不得在摘要中复刻完整历史表格。

LLM 人格设定继续保持稳定，受限记忆与人格分开：人格表示稳定偏好，记忆表示随实验更新的有限认知。

## 失败与兼容

- 旧 Session 没有记忆存储时按空记忆处理。
- 上一轮公开快照缺失时，不向 LLM 提供上一轮个人结果，也不据后台数据补建记忆。
- 模型返回旧格式（只有 `departure_slot` 和 `reason`）时仍可完成决策，记忆保持不变。
- 不修改人类、RL、收费、排队、成本、超时和最终支付逻辑。

## 测试

- 第 1 轮提示不含历史记忆。
- 第 2 轮提示只包含该 Agent 已保存的受限记忆。
- 不同 Agent 的记忆相互隔离。
- 输出记忆被规范化并限制为配置长度。
- 非法或缺失记忆不覆盖上一条有效记忆。
- API 失败及备用算法执行后旧记忆仍保留。
- 关闭开关后不读取、不更新记忆。
- `after_decision` 模式下，记忆和提示均不泄露本轮真实服务率。
- 原有 DeepSeek、RL、组合模式和 `single_bottleneck` 测试继续通过。

## 论文解释口径

LLM 被定义为具有“受限文字工作记忆”的虚拟参与者。它与人类看到相同的公开实验反馈，但通过固定长度的主观摘要保持跨轮认知；RL 则通过数值状态持续学习。三者的可观察环境信息保持一致，内部学习机制不同。
