# 动态服务率 20+40 轮设计

## 目标

将 `dynamic_bottleneck_round` 改为 60 轮正式实验：第 1-20 轮为等概率、轮间独立的随机服务率，第 21-60 轮为状态持续概率 0.8、转移到另外两种状态各 0.1 的对称 Markov 服务率。Human、LLM Agent 和 RL Agent 在决策时获得相同公开信息。

## 自动序列

- 候选服务率保持 `1,2,3` 人/分钟。
- 自动模式名称为 `phased_markov`。
- 第 1-20 轮按 `1/3,1/3,1/3` 独立抽取。
- 第 21 轮开始依据上一轮状态使用转移矩阵；当前状态保持概率为 0.8，转移到另外两个状态的概率各为 0.1。
- 随机种子决定完整序列；相同种子生成相同序列。
- `dynamic_capacity_sequence_scope='session'` 时所有小组使用完全相同的序列。

## 手工序列

增加 `manual_sequence` 模式。研究者通过 `dynamic_capacity_manual_sequence` 填写恰好 60 个逗号分隔的服务率。每个值必须属于候选集合，数量错误、非法值或空配置均在创建 Session 时明确拒绝。手工模式同样对所有组共享。

## 信息边界

- 默认 `capacity_reveal_timing='after_decision'`。
- 参与者只看到候选服务率和“服务率随轮次变化，变化可能存在规律，请自行观察”的说明。
- 不展示第 21 轮切换、随机概率或 Markov 转移矩阵。
- LLM/RL 的当轮决策快照不包含本轮真实服务率、阶段编号或转移矩阵；它们仅能使用与 Human 相同的历史反馈逐步学习。

## 粗收费兼容

自动粗收费依赖本轮真实服务率，若在决策前展示会泄露状态。因此 20+40 默认配置关闭自动粗收费，保留统一手动收费窗口和收费额。收费规则对三种服务率完全相同。

## 数据与兼容性

- 沿用现有逐轮服务率字段和导出结构。
- `dynamic_capacity_draw_mode` 记录 `phased_markov` 或 `manual_sequence`。
- `capacity_probability` 在自动模式下记录当轮实现状态的条件概率；手工模式记录 0，避免将预设序列误表述为随机概率。
- 不修改 `single_bottleneck`。

## 测试

- 60 轮长度、20+40 分段及候选值约束。
- 相同种子复现、不同组在 session scope 下完全一致。
- Markov 阶段条件概率和转移生成正确。
- 手工 60 轮序列原样采用，长度和取值错误会被拒绝。
- after-decision 页面不显示真实服务率、阶段边界、概率或矩阵。
- 动态 app bot、Agent 集成测试和原单瓶颈 bot 回归通过。
