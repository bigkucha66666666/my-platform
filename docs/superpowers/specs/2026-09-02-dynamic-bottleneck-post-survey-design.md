# 动态瓶颈实验后问卷设计

## 目标与流程

新增独立 oTree app `dynamic_bottleneck_survey`，放在动态瓶颈实验之后、最终奖励页面之前。问卷分为两页：第一页测量规律识别，第二页测量跨轮决策策略。Human-only 组回答 7 题；组内存在 API Agent 或 RL Agent 的 Human + Agent 组自动追加 2 道 Agent 感知题。

## 题型

- Q1、Q3–Q6、Q8–Q9 使用 5 点单选题。
- Q2 使用下拉选择，可选“未发现”或正式第 1–60 轮，保留精确轮次同时降低输入错误。
- Q7 保留一句话开放题，用于验证参与者是否真正识别状态持续性。
- 页面不得出现 Markov、后 40 轮存在规律等提示。

## 分组与数据

动态实验创建 session 时，根据每组实际 API/RL Agent 数量把 `H` 或 `HA` 写入 `participant.vars`。问卷 app 同时保存原实验组号、API Agent 数、RL Agent 数和组别类型，保证导出后可以直接合并行为数据。

## 视觉

沿用动态瓶颈页面的深蓝灰、青绿色和浅灰白配色，使用清晰的问卷编号、两步进度条和紧凑问题卡片。桌面端 5 点选项横向排列，移动端自动变为纵向可点击行；不过度使用圆角、渐变或装饰。
