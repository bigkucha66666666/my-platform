# 事故风险动态瓶颈后端原地替换设计

## 目标

在现有 oTree app `dynamic_bottleneck_round` 内原地替换已经废弃的动态容量后端。参与者页面结构、页面顺序和现有交互形式暂时保留；新的后端以《事故风险动态瓶颈_Human-LLM-RL实验方案_最终汇报版》为规则基准，实现事故风险容量、I0/I1/I2 信息处理、固定总需求、Human/LLM/RL 信息公平以及小数服务率结算。

本次不修改前后问卷、数据分析平台、参与者页面视觉设计或正式支付制度。旧 Session 不迁移，新的规则只用于改造后创建的 Session。

## 采用方案

采用原地硬替换，而不是保留双引擎或新建 app：

- 保留 `dynamic_bottleneck_round` 的 app 名、路由、页面模板、同步流程、超时恢复和 Agent 基础设施。
- 删除生产路径对旧 `balanced_shuffle`、`iid` 整数状态和 `phased_markov` 容量机制的依赖。
- 现有 S01–S05 固定序列入口保留，但其后端数据改为事故状态、损失率和实际服务率构成的事故序列。
- 不保留可被正式 Session 意外启用的旧容量兼容开关。

这种方案确保旧研究设计不会继续影响新实验，同时避免复制已经稳定的页面、并发同步、掉线恢复和 Agent 调用代码。

## 实验轮次与行动空间

- 练习轮数为 5，正式轮数为 60，oTree 内部总轮数为 65。
- 练习轮不进入正式收益、正式导出、Agent 长期记忆或 RL 学习状态。
- 正式行动空间固定为 16 个一分钟间隔的出发时刻。
- 默认时刻范围为 07:46–08:01；07:54 仍是自由流条件下恰好于 08:00 到达的出发时刻。
- 现有动态扩张出发时间范围的逻辑不再用于该 app，避免不同 Session 的行动集合发生变化。
- 练习轮采用已知的正常服务率 4.0，让参与者熟悉选择和结果反馈；练习轮不消耗正式事故序列。

## 事故风险配置

新的配置对象只包含事故风险实验需要的参数：

- 正常服务率 `normal_capacity = 4.0`；
- 事故概率 `incident_probability = 0.20`；
- 事故容量损失分布 `Beta(6.83057, 4.05907)`；
- 信息处理 `information_condition in {I0, I1, I2}`；
- 事故序列编号和随机种子；
- 序列作用域固定为 Session。

所有概率、Beta 形状参数、服务率、信息条件和序列记录在创建 Session 时严格校验。服务率必须为有限正数；任何会产生零服务率、非法损失率或不完整60轮记录的配置都拒绝创建。

## 事故序列生成与冻结

每个正式轮次生成一个不可变记录：

```text
formal_round_number
incident_occurred
capacity_loss_ratio
remaining_capacity_ratio
actual_capacity
sequence_id
sequence_seed
```

生成顺序为：

1. 使用 Session 序列种子，以概率0.20抽取是否发生事故；
2. 无事故时，损失率为0、剩余容量比例为1、实际服务率为4；
3. 有事故时，从 `Beta(6.83057, 4.05907)` 抽取损失率；
4. 计算 `actual_capacity = 4 × (1 - loss_ratio)`；
5. 把完整60轮记录冻结到 Session 级状态；
6. 同一 Session 的所有组逐轮读取同一条记录。

`auto` 模式只用于演示和测试，并由明确种子保证复现。正式 Session 必须选择预生成的 S01–S05 事故序列之一。事故序列库直接保存已经抽取完成的60轮记录及生成元数据，避免运行时因 Python 版本或随机实现差异改变正式冲击。

不同处理需要共同随机冲击时，由实验组织者为对应的 H-I0、H-I1、H-I2、HA-I0、HA-I1、HA-I2 Session 选择相同序列编号。系统不根据实验结果筛选或替换序列。

## I0、I1、I2 信息隔离

后端提供单一的决策前公开上下文生成器，人类页面、LLM 和 RL 都从该生成器获得外部信息：

- I0：正常服务率、事故概率、事故损失分布及直观统计量；不包含本轮事故状态、损失率或实际服务率。
- I1：包含 I0 信息和 `incident_occurred`；事故发生时仍不包含损失率和实际服务率。
- I2：包含 I1 信息和本轮实际服务率；后端不要求决策前公开原始损失率。
- 练习轮：明确公开正常服务率4.0，并标识为练习信息，不使用 I0/I1/I2 隐藏规则。

本轮所有选择锁定并结算后，三种信息条件都获得同范围反馈：事故状态、容量损失率、实际服务率、匿名出发分布、匿名分时平均成本以及主体自己的结果。

LLM 和 RL 的决策对象不得直接接收完整事故记录、未来序列、隐藏服务率、随机种子或本轮其他主体选择。上一轮公开反馈仍沿用现有统一快照机制。

## 主体构成与 Session 约束

正式 Session 只允许两种主体构成：

| 条件 | Human | LLM | RL | 有效主体总数 |
| --- | ---: | ---: | ---: | ---: |
| H | 20 | 0 | 0 | 20 |
| HA | 16 | 2 | 2 | 20 |

主体构成是 Session 级条件；信息条件同样是 Session 级条件。同一正式 Session 不允许不同组使用不同信息条件或不同 Agent 数量。原有按组自由配置0–5个 Agent 的生产路径退出。

正式 Session 在创建时验证真人参与者数、LLM 数、RL 数和有效主体总数。演示 Session 可使用缩小人数进行流程测试，但必须显式标记为 demo，且实际排队人数仍等于真人与虚拟主体之和。

每个 Agent 保持独立 ID、人格、文字记忆或 RL 状态，不共享当轮选择。Human、LLM 和 RL 在决策前都无法观察其他主体的当轮动作。

## 连续累计服务与排队

实际服务率保留为浮点数，不进行普通四舍五入、随机整数化或状态离散化。每名主体占用的服务时间为：

```text
service_time_per_actor = 1 / actual_capacity
```

按出发时刻升序处理各批次：

```text
first_service_start = max(departure_minute, next_available_minute)
batch_service_duration = batch_size / actual_capacity
batch_wait = inherited_wait + max(0, batch_service_duration - 1)
next_available_minute = first_service_start + batch_service_duration
```

其中 `inherited_wait = max(0, first_service_start - departure_minute)`。同一出发时刻的主体共享该批次最大等待时间，延续当前页面和实验中的同批次公平规则，不通过随机排序制造同批次收益差异。

所有中间计算使用 Python 浮点值，不提前舍入。事故序列 JSON 中的损失率、剩余容量比例和实际服务率保存到小数点后12位；Player/Group 浮点字段保存原值；展示值保留2位，导出值保留6位。后续队列递推始终使用未格式化的字段值。

## 成本与收益

新事故场景的个体成本为：

```text
total_cost = 2 × queue_delay + 1 × early_minutes + 5 × late_minutes
```

- 旧固定出行成本在本 app 中设为0；
- 旧粗收费和奖励不参与成本或收益；
- 练习轮收益固定为0；
- 正式轮暂时沿用 `max(0, 140 - total_cost)` 的点数换算，以维持现有结果页和支付链路；
- 支付制度后续确定时，可单独替换收益换算，不改变事故、排队或成本记录。

## 模型字段与导出

`Group` 与 `Player` 的服务率字段改为浮点类型，并增加下列逐轮字段：

- `incident_occurred`；
- `capacity_loss_ratio`；
- `remaining_capacity_ratio`；
- `information_condition`；
- `accident_sequence_id`；
- `accident_sequence_seed`；
- `actor_composition`。

自定义导出继续为 Human、LLM 和 RL 各输出一行，并包含：处理条件、主体类型、序列元数据、事故状态、原始损失率、实际服务率、出发时刻、排队、早到、迟到、总成本、收益、决策来源和 Agent 审计信息。练习轮继续排除。

公开反馈快照增加已实现事故状态、损失率和实际服务率，但不增加身份信息。后台聚合可继续从逐轮字段计算；本次不改造数据分析平台。

## 兼容边界与错误处理

- 保留 app 名称、URL、页面类、同步、超时自动选择、掉线恢复、LLM 预取和 RL 更新流程。
- 参与者 HTML 暂不改版；后端继续提供已有模板变量，并为它们赋予新机制下的兼容值。
- 旧 Session 数据不迁移，也不执行数据库删除或重置。
- 若正式 Session 使用 `auto` 序列、主体构成不合法、信息条件不合法、事故序列不完整或服务率非正，创建阶段立即失败并给出明确字段错误。
- 若 Agent 调用失败，回退策略只能使用该处理允许公开的信息。
- 任何公开上下文中出现未来轮次、隐藏事故严重程度或本轮其他选择都视为测试失败。

## 测试策略

严格按测试驱动方式实施：先写一个针对新行为的失败测试并观察预期失败，再写最小实现使其通过。

测试范围包括：

1. 固定种子事故序列可复现，并且无事故轮容量恰为4；
2. 事故轮损失率位于0和1之间，实际服务率等于 `4 × (1-loss)`；
3. S01–S05 每条包含60轮完整记录，并能被正式 Session 冻结和共享；
4. I0、I1、I2 决策上下文严格遵守字段白名单；
5. Human、LLM 和 RL 获得相同的允许公开信息；
6. 正式 H 与 HA 主体构成验证正确拒绝非法人数；
7. 连续小数服务率下，批次等待和跨时刻遗留队列计算正确；
8. 5轮练习不进入收益、导出、LLM记忆或RL学习；
9. 16个出发时刻固定为07:46–08:01；
10. 新成本系数为2、1、5，旧固定成本、收费和奖励不进入结果；
11. 导出包含事故、信息、主体构成和序列字段；
12. 65轮 oTree bot、Agent 单元测试和旧 `single_bottleneck` 回归测试通过。
