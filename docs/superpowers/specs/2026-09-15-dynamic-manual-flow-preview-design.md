# 动态瓶颈手动流程预览设计

## 目标

在“正式实验 · 随机服务率动态瓶颈”的 Session 创建页保留现有快捷方案，另外提供一个手动流程预览区，使管理员可以用 1 名 Human 走完同一场景的真实页面流程。

## 界面

- 手动预览区与快捷实验方案分开展示。
- 提供“启用手动流程预览”开关。
- 启用后显示“预览人数”整数输入框，默认为 1，范围为 1–30。
- 启用后显示“信息条件”选择框，可由管理员选择 I0 或 I1。
- 任一快捷方案被选中时，手动预览自动关闭，恢复正式样本量和标签规则。

## 后端边界

- 新增 Session 配置标记 `flow_preview_enabled`，默认为 0。
- 只有在正式动态瓶颈场景且该标记为 1 时，才进入预览模式。
- 预览模式只允许一个 Human-only 小组，人数为 1–30，不创建 LLM/RL Agent。
- 预览模式跳过“H 组必须 30 人”和 Room 标签预绑定；正式模式的现有校验不变。
- 预览依然使用正式场景的 3 轮热身、30 轮正式实验、固定服务率序列、信息条件页面和收益计算。
- 不给预览数据伪装正式 H/HA 样本构成；会话配置中保留预览标记，便于导出后识别。
- 动态场景自定义导出包含 `flow_preview_enabled` 列，预览行标记为 true，非预览行为 false。

## 验证

- 后端单元测试覆盖预览标记、I0/I1 选择、1 人预览通过和非法 Agent/多组预览被拒绝。
- 模板契约测试覆盖手动预览开关、人数输入和 I0/I1 选择。
- 现有正式分组、Room 标签、动态场景单元测试和 bot 流程必须保持通过。
