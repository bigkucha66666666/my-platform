# 瓶颈全部通过时间计入额外行程

用户明确：瓶颈通过时间全部额外计入行程，不扣除服务时间窗。
本次仅修正 `dynamic_bottleneck_round`，不修改旧单瓶颈场景。

额外时间 = 前序积压等待 + 同时出发人数 / 本轮服务率 × 服务时间窗。
到达时间 = 出发时间 + 固定行驶时间 + 额外时间。
沿用同一出发时间组统一结算的实验设定；空批额外时间为零。

第三题：07:54 出发，固定行驶 6 分钟，6 人、服务率 2 人/分钟，
全部通过需 3 分钟，正确到达时间为 08:03。
后端统一结算及 RL 备用策略的估算均使用上述规则。
旧文档中该例的“等待 2 分钟、08:02”已被本说明取代。

文献边界：Arnott、de Palma、Lindsey（1990）第 114 页定义
总行程时间为固定时间加瓶颈等待时间，个人等待为加入时的队列长度除以服务率。
本实验保留“同时间整批统一按全部通过时间结算”的简化，不应将该简化
描述为原文逐个连续个体的规则。
原文：https://web.mit.edu/14.573/www/bottlenecks.pdf

验证：回归覆盖满批、未满容量、积压、连续服务率及 Agent 成本估算，
并运行场景全套单元测试和 oTree Bot。不会重算既有数据，不重置数据库。
