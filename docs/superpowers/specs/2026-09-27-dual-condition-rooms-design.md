# I0/I1 双房间设计

用户确认：两个房间分别监控同一信息条件下的一个 Session，每个 Session 40 名真人，沿用现有顺序标签分组。

新增 `prod_room_i0` 与 `prod_room_i1`，保留 `prod_room`、`demo_room`。两个新房间共享既有 `_rooms/econ101.txt`，Room→Session 绑定与标签查找均使用 oTree 原有 Session 作用域，不新增全局标签分配逻辑。

每个新房间创建动态瓶颈正式场景时，首次自动应用已有 `PAIR-I0` 或 `PAIR-I1` 快捷方案：P001–P030 为 H，P031–P040 为 HA；HA 内部继续使用 10 Human、10 LLM、10 RL。退出预实验或单人预览时恢复当前房间对应方案。管理员仍可主动改用已有快捷或自定义方案；房间名是默认配置提示，不是后端锁定条件。

不新增 SESSION_CONFIG、不改首页、不改变成本、奖励、服务率序列、RL、问卷或 Room 安全机制。两个 Session 比较时需手动选择同一 S01–S05 序列；不做跨 Session 轮次同步。旧房间和非动态场景行为保持不变。配置在服务进程重启后生效，不重置数据库、不创建实际 Session、不做 Git 提交。

测试覆盖：新旧 Room 注册与标签路径；房间到默认快捷方案映射；默认配置只在首次进入正式场景时应用；顺序分组和同名标签跨 Session 独立；既有管理员模板及 Room 兼容回归。
