# 保留完整实验流程的房间同步改进方案

日期：2026-10-07。基线：`a202ebf`。状态：2026-10-08 本地实现、隔离验证与独立整体修正复核完成；未部署，服务器与分布式浏览器启用门槛见交接文档。

## 1. 用户要求与范围

只完善参与者同步，不删减、合并或跳过实验步骤，不新增管理员操作或监控界面。

保留现有进入房间与标签分组、说明与理解测试、热身说明和 3 轮热身、正式说明和 30 轮正式实验、各轮准备与决策、各轮结果、最终问卷、支付与结束页。页面外观和参与者操作保持现状，只修改同步状态及必要的连接提示。

保留现有 Room 监控能力和房间绑定。I0、I1 两个 Session 独立运行；每个 Session 的 H、HA 真人统一同步。现有每房间 40 名真人、H30 与 HA10 真人及 HA 的 LLM/RL 配置不变。容量序列、成本、信息条件、Agent 策略及奖励规则不因同步修复而改变。

## 2. 已有证据及边界

依据 `docs/同步修复复测与启用条件_2026-10-07.md`，服务器隔离测试中锁前入口至业务处理的等待最大约 23.78 秒，浏览器显示同步未满足原 T+2 秒目标。不能把这些等待全部归因于本机集中运行浏览器。

源码确认：oTree HTTP 与 Live 消息共用全局事务锁；`room_release_snapshot` 的状态读取和无条件写回会标记整个 Session.vars 为待保存，Participant.vars 读取也有类似行为。结果处理亦使用该事务通道。这些是实际存在的阻塞与额外写入路径，但各自贡献仍须分项测量，不宣称已找到全部耗时来源。

报告记载正式服务仍使用旧入口且未启用新协议。这不是本轮已实时验证的生产状态，也不能靠仅开协议开关解决同步延迟。

## 3. 路线选择

路线 A：只减少现有轮询和重复写入，保留所有消息走 oTree 事务。变更较小，但慢请求仍可能阻塞放行及决策接收。

推荐路线 B：保留所有页面和业务规则，缩短现有同步路径，并将同步控制、选择接收与结果业务处理隔离。所谓隔离仅指后台执行路径，不是取消结果处理、Agent 决策、准备页或任何实验步骤。

不采用逐人进入页面后分别计时，不增加管理员逐轮点击开始，不直接删除 oTree 全局锁，也不靠任意增加 worker 绕过当前单进程假设。

## 4. 同步规则

### 4.1 准备与统一放行

每轮仍先完成现有准备过程并预加载决策页。同步确认必须来自该参与者当轮页面的真实加载回执，不能用 Room 中“在线”或已进入房间代替。

同一 Session、同一轮次只有一个放行时间 T 和截止时间 T+60。重复 ACK、状态查询、刷新和重连都不重置该时间。两个 Session 使用各自状态，不能按可重复的实验标签直接共用状态。

维持现有准备超时与缺席规则；服务器队列、页面失败或缺失回执造成的技术故障不能被改记为参与者缺席。技术异常保留为异常，不自动把未同步的轮次宣称为有效同步数据。

### 4.2 信息显示与客户端计时

继续按服务器可信时间判定放行和截止，浏览器单调时钟用于估计显示时间，不能决定提交是否准时。页面复用原时间窗口，已提交或截止后不能重新获得 60 秒。

I0 作出当轮选择前不能读取实际服务率；I1 只能在 T 到达后获得本轮实际服务率。预加载页面、同步响应和前端缓存均遵守该限制。所有参与者仍按原规则在结果阶段看到公开反馈。

状态请求限制为每页面至多一个在途请求；请求超时后重试，避免无响应时继续堆积轮询。状态查询不重复写入已确认的 ACK、放行时间或整块历史数据。

### 4.3 决策接收与业务保存

在 oTree 事务排队前记录服务器可信到达时间。轻量接收记录必须包含经过认证的 Session、轮次、参与者、页面及选择，且在持久化成功后才能回报已接收；内存登记不能冒充可靠保存。

合法选择按锁前到达时间区分准时与迟到。准时收到但稍后处理的决定保留为 manual，不能因数据库处理开始晚而变成超时补选。持久化失败或超过规定处理上限必须报告技术异常，不得悄悄生成缺席决定。

接收回执不等于实验结算完成。原 oTree 表单校验、Player 数据保存、轮次推进、成本计算、结果页及全部最终流程继续执行；结算前核对该轮有效接收记录已被正确保存。重复请求不得覆盖已确认或已结算决定，跨参与者和跨轮次不得串扰。

### 4.4 可操作回执

可操作回执按 Session、轮次、参与者与页面实例关联，不能只依赖发送时仍处于 Decision 页。补测参与者打开后立即提交、POST 先于回执处理的顺序，避免转入结果页后回执被忽略。

该记录是同步审计证据，不是参与者的选择。缺失回执不能直接解释为未看到页面或行为缺席。

## 5. 实现与兼容约束

同步状态和接收数据使用最小字段的独立持久化记录，避免轮询携带并保存完整的 Session/Participant 历史。采用本机独立 SQLite 同步日志（WAL、完整同步落盘），通过 `DYNAMIC_ROOM_SYNC_DB` 指定路径；不混入 oTree 6 的内存数据库或覆盖正式 PostgreSQL。部署时必须为该文件配置持久目录与备份，不支持共享网络盘或多主机 worker。接入身份在现有 Decision 页面生成并绑定当前会话和轮次，接收端不信任客户端上报的身份、时间或其他房间数据。

轻量控制路径不调用结果计算、Agent 决策或 oTree ORM 模型事务。新协议使用同源签名 HTTP 控制请求；oTree ASGI 业务保留单独的线程与事件循环，桥接请求与响应，仍保持原全局锁和单业务 worker。同步日志操作在受控线程池完成。隔离方案须同时检查事件循环阻塞，不能仅增加一个仍被同步计算阻塞的异步路由就宣称解决。

先保留单业务 worker。新的持久化表、状态更新幂等性、进程重启和故障恢复均在隔离环境测试，不能用进程内缓存作为唯一事实来源。状态源只有一份；oTree 侧同步镜像不另行决定 T。

新方案采用新会话协议标记。已存在或正在进行的 Session 不半途迁移。旧协议仍能运行。涉及新表与入口的部署步骤单独列出，本轮不自动修改正式服务器、开关、数据库或服务命令。

## 6. 验证与完成标准

1. 先补失败测试：纯 status 无重复历史写入、重复 ACK 幂等、两个房间隔离、旧页面回执、I0/I1 信息时点、刷新与重连。
2. 冻结 Player 的实际 GET/POST 与表单校验仍通过。并发选择包含非法值、重复、早到、真正迟到，以及 T+59 秒集中到达后排队处理。
3. 40/80 真人负载分别验证后台入口、持久化接收、事务等待和响应时间；不得仅放宽测试阈值。轻量请求不能被人为注入的慢结果处理阻塞。
4. 保留既有 T 至 T+2 秒的健康客户端可操作目标，用含误差范围的显示记录验证；服务接收时间不是浏览器真实显示时间。慢客户端或技术失败须记录，不作无条件“绝对同时”保证。
5. 回归完整 33 轮及原问卷、支付、结束页，检查 30 轮正式成本、H/HA Actor 数量、Agent 记录唯一性、选择来源和现金金额。不能为改善同步测试而删减流程或更改实验规则。
6. 本机不再集中启动 80 个独立 Chrome；后台低资源并发与少量真实浏览器分开测，分布式浏览器性能验收留给服务器隔离测试。每次测试使用唯一进程集并及时退出本次创建的进程。
7. 交付分别说明已经通过的本地测试与尚未完成的服务器验收，不把源码修改等同于上线完成。本轮不自动 Git 提交或部署。
