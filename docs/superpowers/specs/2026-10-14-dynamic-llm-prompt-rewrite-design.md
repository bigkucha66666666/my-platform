# 动态瓶颈 LLM 提示词整体改造设计

日期：2026-10-14

## 已确认范围

采用“完整重写提示词 + 明确时间参照”的方案，仅修改 `dynamic_bottleneck_round` 的 LLM。保留人格、自主选择、I0/I1 信息条件、历史反馈与受限记忆机制；不修改 RL、原始单瓶颈、排队结算、轮次、问卷或现金报酬。

本次目标是让实验规则表达清楚、决策说明与行动保持一致，并能追踪提示词版本。不是使 Agent 强制最优、每轮保持相同选择，也不保证真实 API 行为或成本必然改善。

## 提示词结构

完整重写系统指令和用户指令，以清楚的中文说明角色、规则、信息边界、历史依据、选择要求和 JSON 输出。保留上下文现有字段含义，不靠替换模型、人格或提高思考预算同时改变多个实验因素。

规则必须从传入的 `cost_parameters` 读取，不能把当前数值硬编码成永久规则：

- 到达时刻 = 出发时刻 + 固定行程分钟数 + 本轮额外瓶颈行程 / 排队延迟。
- 额外瓶颈行程非负。早到分钟 = max(目标到达时刻 − 实际到达时刻, 0)；晚到分钟 = max(实际到达时刻 − 目标到达时刻, 0)。
- 成本按平台给定的固定成本、排队、早到、晚到费率计算。当前场景没有额外通行收费，不因为 JSON 留有 tolls / rewards 字段就虚构收费或奖励。
- 人格影响风险偏好、适应速度和选择惯性，不改变真实时钟、固定行程或平台的客观成本系数。
- 避开拥挤时刻可能降低排队，但更晚出发会推迟固定行程到达基准，不能把“更晚”解释为“更早到达”或自动减少晚到。

## 每档固定行程参照

在新版 LLM 请求的合法档位中派生一个到达基准：`departure_minute + free_flow_travel_minutes`，同时保留数值和时钟显示。该字段只使用所有主体均已获知的出发档位和固定行程，不引入隐藏服务率、未来序列、当轮选择或队列预测。

明确注明：此值忽略额外瓶颈行程，是实际到达时刻的下界 / 时间换算参照，不是实际到达预测，也不是该档预期总成本。所有原有档位保持可选；即使基准已经晚到，也不由程序禁止模型选择。

当前参数下，用 07:54 → 08:00、07:57 → 08:03、07:59 → 08:05 验证换算，提醒 07:59 出发不可能因避免排队而在 08:00 到达。这些数值作为测试，不固化成提示词唯一配置。

## 信息、历史和记忆

I0 作选择时只能使用分布和已有公开反馈，不得读取当轮实际服务率；I1 可以使用已公开的当轮精确服务率，但仍不知道其他主体的当轮选择。历史公布的服务率属于对应的历史轮次，不能直接当作本轮已知值。

上一轮个人结果及公开统计是观察事实；空档的历史成本为未知，不是零成本，也不保证本轮无人选择。受限记忆是可修正的个人印象，与结构化事实矛盾时以事实为准。当前选择、主观预计及尚未获得的当前结果必须区分，不能提前把当前选择记成已发生的结果。

不新增完整逐轮历史，不把热身结果泄漏到正式首轮，不替 Agent 推断真实隐藏容量。人格不变，也不人为惩罚每次换档来强制稳定。

## 输出契约与实现边界

仍返回单个 JSON，保持 `departure_slot`、`reason` 和启用记忆时的 `memory_summary` 契约。要求档位为合法整数，理由只解释最终选定档位，描述的时刻必须对应该档；若分析中改选，应统一最终输出，不保留互相冲突的候选结论。记忆摘要不得重复互相矛盾的行动。

理由简短，只陈述必要依据，不要求输出冗长思考过程。保留现有响应预算、温度、模型、timeout、调用次数、合法档位校验及 API 错误回退。此次不新增按自由文本猜测档位的解析器、自动重试、强制最优求解器或对正常但高成本选择的自动替换。

输出一致性目前是指令要求和离线契约检查，不声称自然语言理由可被后台完全机械验证。真实调用改善仍需后续小规模检验。

## 提示词版本与历史数据

新增可区分的提示词版本，并在新 Session 创建时固定到配置，在后续每次 LLM 决策记录和导出中显示。模型版本与提示词版本分开，不能继续仅凭 `deepseek-v4-flash` 判断两批数据使用相同指令。

新建 Session 使用新版；旧 Session 配置没有提示词版本时视为旧版，继续使用对应旧提示词，避免部署后将正在运行的 Session 中途切换。历史决策、记忆和 CSV 不重写、不回补新版本标签。旧记录没有版本字段时导出留空，并说明该字段缺失不能证明使用新版。

需要保留最小旧版提示词路径来读取旧 Session；不得为兼容而更改新旧两版的信息条件或队列规则。新旧版本只改变规则表达和公开时间换算参照。

## 验证与交付

先写失败测试，再实现和回归。使用现有 conda 环境，不安装依赖，不启动长流程、压力测试或浏览器。离线回归不调用真实 API；用户于 2026-10-15 追加授权后，可在离线通过后做 3 轮新旧提示词对照，总计最多 6 次真实请求，使用独立模拟市场而非已有 Session 或正式 S01–S05 序列，不额外重试。

- 固定行程参照与档位匹配，支持不同固定行程参数，不修改传入的原始上下文。
- I0 请求不存在当轮实际服务率或未来序列；I1 保留已公开服务率，均不包含他人的当轮决策。
- 提示词清楚说明时刻与成本、事实与记忆、空档未知、最终输出一致性；人格和原有候选档位不改变。
- JSON 回应仍由原有解析和回退链处理，单次调用、预算、超时和模型参数不变。
- 新 Session 固定新版；旧 Session / 旧记录保持兼容，新旧版本标识可追踪，读导出不修改数据。
- 相关 Agent、分组和导出回归通过；交付具体改动、验证范围及新建 Session 的启用方式。

保留工作区已有同步机制和论文改动。不自动 Git 提交，不修改服务器、不重启线上服务。离线测试通过不等于模型稳定性已经经真实调用证明。
