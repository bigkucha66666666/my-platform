# 单个 Session 数据直接导出设计

日期：2026-10-14

## 需求与已确认方案

管理员需要直接下载指定 Session 的数据，不再从全部 Session 数据中手动筛选，也不受管理员当前查看的应用或轮次影响。用户已确认在具体 Session 的 Report 页面增加两个按钮，下载 Excel 可打开的 CSV；本次不实现 ZIP 打包或原生 XLSX。

1. **导出本 Session 全部轮次**：分析用长表，每个主体每轮一行，覆盖热身和正式轮次，包含已保存的 Human、LLM、RL 数据。
2. **导出本 Session 全部原始数据**：oTree 原始宽表，包含该 Session 各应用的记录，包括实验轮次、问卷及结算页面的已保存字段。

保留现有全局 Data 导出和现有只导出正式轮次的 `custom_export`，不改变其字段含义或分析口径。入口仅添加在动态瓶颈场景的 Report 内容中，不修改首页、其他场景或参与者页面。

## 当前代码依据

- `dynamic_bottleneck_round/admin_report.html` 已有 Session Code 展示。
- `vars_for_admin_report` 已提供当前 Session 编号及全部轮次报告数据。
- 当前场景为 3 轮热身、30 轮正式实验；导出按目标 Session 实际保存的轮次记录读取，不把轮次数写死为 33，以兼容旧数据。
- 历史阶段定义优先读取保存的热身数，其次依据保存的正式轮数与预创建总轮数识别热身区段；元数据缺失或不符合项目轮次结构时使用当前场景默认值，原始轮号始终保留，早期数据做阶段比较前应核对当时规则。
- 现有 `custom_export` 和 `agent_decisions_for_players` 排除热身，不能直接作为新的全部轮次导出。
- 虚拟 Agent 决策保存在组内代表参与者的变量中，需按 Session、组和原始轮次读取、去重，不能将这些主体当成额外的 oTree 真人 Player。
- 本地现有 conda 环境为 oTree 6.0.13；其原始宽表导出函数支持显式传入 `session_code`。不能仅根据本地 URL 格式推断服务器版本的行为。
- 工作区已有同步机制改动和论文文件变动，本功能不得覆盖、回退、提交这些无关改动。

## 数据口径

### 全部轮次长表

必须能区分 Session、处理条件、组、主体及轮次：

- `session_code`、`group_id`、`treatment_condition`、`information_condition`。
- `actor_type`，真人的 `participant_code` / `participant_label`，虚拟主体的 `agent_id`。
- 原始 `round_number`，`round_phase`（`warmup` / `formal`），阶段内 `phase_round_number`；热身的 `formal_round_number` 留空，正式轮次从 1 编号。
- 已保存的服务率、出发选择、排队、到达、早到、晚到、成本、收益、决策来源、Agent 回退信息及必要的有效性标记。
- `results_ready` 明确表示该组该轮是否已结算。

Human 导出目标 Session 已创建的轮次记录，包括尚未完成的记录；未选择的决策字段留空，未结算的结果字段留空，不把默认零值解释为实际结果。已经真实结算得到的零成本或零排队仍保留为零。

LLM / RL 仅导出已经保存的虚拟决策，不为未进行的轮次生成虚构的主体记录。热身存在 Agent 记录时一并导出；没有记录时不补造。按 Session、原始轮次、组、主体身份去重。

输出按原始轮次、组、主体稳定排序。不能把热身显示为正式第 0 轮，不能把未完成轮次误称为已完成轮次。同步诊断字段只读取现有记录，不能因导出而初始化放行状态、生成技术异常或改变实验状态。

### 全部原始数据宽表

显式将当前 Session 编号交给 oTree 原始宽表导出函数，不依据当前显示的 Round 或应用筛选。保留 oTree 字段名称和原始结构，用于备份、问卷及结算字段核查。

宽表的一行通常对应一位真人参与者，各轮字段横向展开；不声称它具有单独的虚拟 Agent 行。虚拟主体的结构化轮次分析使用前一个长表按钮。导出的是数据库已有字段，不额外暴露运行环境、API 密钥或服务端配置文件。

## 页面与后端边界

Report 页面 Session Code 附近添加两枚按钮及一句说明：“全部轮次包含热身和正式轮次；未完成记录保留为空，原始数据为宽表。”两个按钮均绑定页面所属 Session，不需要输入编号。

新增项目级导出模块，分别负责目标 Session 校验、只读长表构建、CSV 响应和原始宽表适配。管理员下载端点复用 oTree 管理员认证机制，接入当前项目应用的路由及初始化流程，不通过外层无认证 ASGI 下载入口绕过保护，不修改环境中的 oTree 安装文件。

请求必须提供有效 Session 编号；缺失、不存在或目标 Session 不包含动态瓶颈场景时返回明确错误，绝不退化为全部 Session 导出。未登录请求按平台管理员访问规则拒绝或跳转登录。只支持固定的两种导出类型，不允许通过请求指定任意 Python 函数或文件路径。

CSV 使用 UTF-8 BOM，按标准 CSV 规则处理中文、逗号、引号和换行；新长表中的可编辑文本需避免被 Excel 当作公式执行。文件名包含 Session 编号和导出类型，例如 `session_0a80wnxy_all_rounds_YYYY-MM-DD.csv`。

导出不调用 LLM、不训练 RL、不触发结算、不更新同步时钟、不改变参与者进度或实验轮次。管理员页面现有的报告生成行为与本功能新增的下载行为分别核验，不把原有报告逻辑的副作用隐藏在下载实现中。

## 验证与完成标准

使用现有 conda 环境和隔离测试数据做针对性测试，不修改正式数据库，不启动长期压力测试或额外浏览器进程。

- 两个不同 Session 同时存在时，两个按钮的输出均只包含目标 Session。
- 真人热身和正式轮次完整读取、正确编号；已保存的 LLM / RL 记录不遗漏、不重复。
- 未完成轮次的选择和结算字段不会伪造为零或已完成。
- 原始宽表覆盖目标 Session 的各应用和全部轮次，不受 Report 当前选中轮次影响。
- 缺失编号、无效编号、非目标场景、未登录等请求正确处理，无全库导出回退。
- 中文与特殊字符能经标准 CSV 解析器往返读取；长表可编辑文本的公式风险受控。
- 导出前后数据库记录、参与者变量及同步持久化状态保持不变；无 Agent API 调用。
- 实际框架路由与模板渲染能得到两个正确的下载链接，不只做静态字符串检查。

完成交付时说明按钮位置、两种文件的数据形态、测试覆盖和部署边界。本地修改不代表服务器已上线；若无法验证服务器所用 oTree 版本，明确说明该兼容性验证尚未完成。
