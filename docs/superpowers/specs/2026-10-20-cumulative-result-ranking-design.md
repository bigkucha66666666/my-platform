# 正式结果页个人累计排名

## 已确认的需求

用户选择“截至当前轮的累计正式成本组内排名，包含 Agent”，并确认相同完成轮数时累计成本与平均成本排序相同。用户明确本次不修改奖励机制。

- 每轮正式实验结果页显示本人截至当前轮的正式平均成本、组内排名、比较主体数和已完成正式轮数。
- 比较范围为同一组全部真人、LLM、RL；自动补选作为实际已结算选择计入。
- 热身不计入累计，也不显示排名。只使用已经完成的正式轮，不能读取未来轮的初始零成本。
- 成本越低排名越靠前。累计成本按六位小数比较以消除浮点尾差，同分并列，采用 1、1、3 的名次规则；不随机打破并列。
- 页面只提供本人名次，不公开其他主体身份、个人成本或完整排行榜。平均成本显示四位小数并注明显示值经过四舍五入。
- 奖励、报酬规则、付款代码、原始成本与收益、Agent 决策输入保持原样。

## 数据与兼容

新建 Session 保存排名规则版本；既有 Session 保留原反馈，不在中途追加排名。没有新增数据库字段，不需迁移或重置数据库。

在既有组结算锁/事务内，一次计算该组全部主体的累计成本和名次。组内第一位真人的私有 participant.vars 保存上一正式轮累计总额及轮次，各真人自己的 vars 按原始轮号保存本人的结果快照。

下一正式轮只能承接紧邻上一轮的完整总额，且主体集合必须相同。若历史不完整或主体数量不符，不虚构零成本排名、不阻塞既有成本/报酬结算；排名区域显示暂不可用。重复结算沿用 results_ready 快速路径，不重复累加。

结果页仅在当前组结果就绪后读取本人对应轮次快照。页面刷新不扫描历史，不产生排名写入；后来轮次完成也不改变之前的结果页名次。排名数据不加入匿名公共反馈或 Agent 上下文。

## 页面

沿用现有结果页的颜色、字号和卡片边框，在本轮行程与成本分解之间增加个人排名卡片。主信息为“第 X 名 / N 个主体”，并列时明确显示“并列”。旁边显示“截至正式第 R 轮”和“平均成本”。窄屏改为纵向排列。

## 验证

纯函数验证累计与单轮名次不同、平均成本等价、并列、六位精度、非法成本、缺失/变化主体、轮数与前序不一致。

应用验证热身和旧 Session 不显示、未结算不显示、缺失历史不伪造、组间隔离、私有快照稳定和幂等。

真实 oTree 隔离 ORM 验证 H9 和 HA(3+3+3) 连续两轮，独立重算名次/平均成本；真实 HTTP 渲染检查自己的卡片与隐私，并确认排名读取不改成本/收益/报酬变量。兼容 5.11.5 与 6.0.13。尽可能检查桌面与手机宽度，明确没有服务器部署或真实设备验证。
