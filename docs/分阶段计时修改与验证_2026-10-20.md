# 分阶段计时修改与验证

本地实现完成，尚未发布服务器、操作既有数据库或 Git 提交。

## 最终规则

| 阶段 | 原始轮次 | 决策最长时间 | 结果页最长时间 |
| --- | --- | --- | --- |
| 热身 3 轮 | 1–3 | 60 秒 | 50 秒 |
| 正式第 1–10 轮 | 4–13 | 60 秒 | 40 秒 |
| 正式第 11–20 轮 | 14–23 | 40 秒 | 30 秒 |
| 正式第 21–30 轮 | 24–33 | 30 秒 | 30 秒 |

这些是上限，不在个人提交后额外追加一段固定等待。原有选择齐备后结算、结果页提前点击下一轮、同一 Session 统一放行的流程保持。配置时长全部用满时，决策与结果页合计 43 分 50 秒；这不包含说明、准备/同步、问卷和网络等耗时，也不是实测整场时长。

## 实现与兼容

- `dynamic_bottleneck_round/round_timing.py` 提供完整 33 轮规则和统一读取入口。新建 Session 在 `Session.vars['dynamic_bottleneck_round_timing_v1']` 保存 JSON 快照，版本为 `staged_v1`。
- 未保存新快照的已有 Session 仍使用 60 秒决策、50 秒结果。不会批量修改历史 Session、成本、付款或旧同步日志。
- 普通页面、协议 1、协议 2 读取相同快照；同步状态在首次初始化时保存 `decision_seconds`。重复初始化、刷新和重复 ACK 不改已有截止；旧状态缺少新字段时继续使用 60 秒。
- Decision、RoundStartSync 及放行提示显示当轮时长；Results 使用 oTree 原生首次呈现的超时缓存，刷新不重新开始计时。
- 准备时限、5 秒放行提前量、10 秒排空保护、真实缺失 ACK/技术异常、首次有效回执和未结算 Results 保护保持原语义。
- 本轮没有修改业务模型字段，不需要新增业务表字段。

发布代码时必须包含新模块 `round_timing.py` 及相关应用、模板、JS 和同步集成变更；只升级 oTree 或只复制依赖文件不会实现分段计时。仍按原部署说明固定 Python 3.10 / oTree 6.0.13。规则对新建 Session 生效。
