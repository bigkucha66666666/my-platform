# 单个 Session 数据直接导出

## 从哪里进入

登录管理员后台，进入 **Sessions → 指定 Session → Report**。在动态瓶颈服务率报告的 **Session Code** 下方有两个按钮：

| 按钮 | 下载内容 | 主要用途 |
| --- | --- | --- |
| 导出本 Session 全部轮次 | 一个主体一轮一行；包含热身、正式轮次及已保存的 Human / LLM / RL 记录 | 逐轮成本、决策、分组和不同主体比较 |
| 导出本 Session 全部原始数据 | oTree 原始宽表；一位真人一行，应用和轮次字段横向展开 | 原始字段核查、问卷和结算页面已保存字段备份 |

两种文件都是带 UTF-8 BOM 的 CSV，可以使用 Excel 打开，不是原生 `.xlsx` 工作簿。文件名包含 Session 编号及日期，例如 `session_0a80wnxy_all_rounds_2026-10-14.csv`。

在 Report 中选择哪一轮不影响这两个按钮的导出范围。两个按钮自动绑定所在页面的 Session，不需要筛选全平台数据。

## 全部轮次的含义

当前场景为 **3 轮热身 + 30 轮正式实验**。长表使用原始 `round_number`，并提供 `round_phase`、阶段内 `phase_round_number` 和 `formal_round_number`。

- 热身：`round_phase=warmup`，正式轮次编号为空。
- 正式实验：`round_phase=formal`，正式轮次从 1 编号。
- 尚未选择：出发字段为空，而不是出发时刻 0。
- 尚未结算：结果字段为空；`results_ready=0`，而不是成本 0。
- 真实已结算的零成本、零排队：仍保留数字 0。
- 虚拟 Agent：只导出已保存的决策；不会为未来轮次生成虚构记录，或把代表真人的结果复制到 Agent。

服务率单位为 **人/分钟**，排队 / 早到 / 晚到 / 行程时长单位为分钟，成本与收益为实验积分。出发 / 到达时刻同时保留已有的分钟数及时间文字。货币类型字段在长表中编码为数字，不带“积分 / points”显示后缀，便于统计。

原始宽表保留 oTree 原有字段结构和默认值；未完成记录的判别应使用长表，不能将宽表中的默认 0 全部视为真实行为结果。宽表可能因平台其他历史数据存在更多轮次列，目标 Session 没有这些轮次时对应列为空；不代表导出了其他 Session。

原始宽表不提供单独的虚拟 Agent 行，也不是对所有内部变量 / 日志 / 配置文件的完整备份。需要结构化 Agent 轮次数据时使用第一个按钮；如果结算页尚未产生记录，导出不会执行付费结算来补齐它。

## 旧 Session 是否可用

**可以读取原数据库中的已有动态瓶颈 Session，不要求重新创建或重跑实验。** 本功能没有数据库迁移，也不修改已有选择、收益、轮次和参与者进度。

长表按目标 Session 实际保存的轮次读取，不写死最多 33 轮。阶段识别优先使用保存的 `warmup_rounds`；没有该项时，依据项目保存的正式轮数 `payoff_rounds` 与实际预创建的总轮数识别小的热身区段；旧记录缺少或不符合该元数据时回退当前场景默认 3，并始终保留原始轮号供核对。特别早期或手工变更计分轮数的 Session，应核对当时的热身规则后再做阶段比较。

旧虚拟主体只有 `payoff` 而没有 `payoff_unrounded` 时仍保留已保存的收益；两个字段都缺失则为空，不补造零值。历史数据中未保存的 Agent 记录、成本或问卷答案，不能通过新增导出恢复。

部署时 **必须保留服务器原有数据库**。不要执行 `otree resetdb`、删除数据库或用本地数据库覆盖服务器数据库。

## 服务入口与文件同步

此功能注册在项目既有的 `project_asgi.py` 入口中，继续使用项目现有的 `project_prodserver.py` 启动方式，保持原来的同步协议、环境变量和单 worker 设置。

功能涉及以下源码文件，部署时必须一起同步：

- `session_data_export.py`
- `session_data_export_views.py`
- `project_asgi.py`
- `dynamic_bottleneck_round/__init__.py`
- `dynamic_bottleneck_round/admin_report.html`

更新代码后需要按服务器原有部署流程重启服务，再刷新管理员页面。本次本地工作没有重启或更改服务器。

如果仍通过原生 `otree prodserver` / `otree devserver` 启动，项目导出路由没有被加载，Report 会显示“单 Session 导出尚未加载”和项目入口提示；不会显示一个暗中导出全平台的替代链接。不要为导出关闭管理员认证。

## 安全与只读边界

下载请求使用 oTree 管理员认证；编号必须明确有效，目标不存在返回 404，非法类型或非动态场景返回 400，绝不会退回全部 Session。文件响应禁止缓存。

长表只读取已保存字段、变量与同步记录，不使用具有初始化或故障持久化副作用的现有导出辅助函数。同步数据库通过 SQLite 只读模式读取；不会新建、修复、推进时钟或持久化进程内故障。若已初始化轮次的同步快照缺失，长表明确标记 `room_release_export_audit_status=unavailable` 并标为不适合直接行为分析；这不是对实验状态写入新异常。已有文件读取失败时返回 503，不继续输出不可靠的诊断数据。

原始宽表仍调用 oTree 导出函数，但禁止读取过程自动刷新变量标记；仅清理 getter 对未改变变量产生的新增脏标记，不回滚业务字段或已有改动。两种下载都不调用 LLM / RL、不结算、不改变实验流程。

## 本地验证结果

环境：已有 conda `otree_env`，Python 3.10，oTree 6.0.13。未安装依赖，未启动浏览器或 HTTP 服务器。

新增导出测试 **21 项通过**：19 项纯函数测试，2 项真实框架隔离子进程测试。框架测试实际执行 HTTP、管理员认证、模板渲染和下载，覆盖：

- 两个各有 2 位真人的 Session 相互隔离。
- 目标 Session 2 × 33 = 66 条真人行，另有 4 条已保存的热身 / 正式虚拟 Agent 行。
- 全部轮次与阶段编号、未完成字段为空、真实零值不丢失。
- 已保存问卷答案和结算应用字段进入原始宽表。
- 未登录、未知 Session、无效编号、非法类型和非目标场景正确处理。
- 路由重复注册不会生成重复入口；Report 的第 1 / 4 轮均绑定同一 Session 下载链接。
- 协议 1 不创建同步文件；协议 2 读取已有 journal 及进程内故障，但不改写同步历史。
- 完整下载请求包括框架提交阶段，SQL 事件观察到 **0 条 INSERT / UPDATE / DELETE / REPLACE**；前后各模型表与同步记录一致。

服务率、Agent 集成、管理员模板和生产启动器相关回归 **97 项通过**，合计 **118 项通过**。相关源码编译检查与本功能涉及文件的 diff 空白检查通过。全仓库 diff 空白检查发现原有论文日志的尾随空格，未改动这些无关文件。
