# 双房间独立实例：运行说明与本地验证

本次完成本地第一批隔离改造及第二批条件固定。没有连接或修改 ECS，没有迁移数据库，也没有提交 Git。统一公网入口、完整并发流程仍需后续验收。

## 为什么能减少等待

I0/I1 原来是两个 Session，共用一个业务进程和原生事务锁。现在每个实例运行一个 Web worker、一个自己的超时子进程，使用不同数据库、journal 和 Agent 预取目录。I0 的慢业务请求不会再进入 I1 的业务队列。

这可减少跨房间排队；同房间等待 H/HA 两组就绪、Agent 决策、单组结算、结果查看时长和新 Session 的 3 秒放行提前量仍按原规则执行。共享主机的 CPU、内存、磁盘及 PostgreSQL 服务仍可能互相影响，不能承诺整体耗时减半。

## 修改内容

| 文件 | 用途 |
| --- | --- |
| `instance_config.py` | 一次校验两个实例，规范化路径和数据库目标，构造清洁环境，生成并校验固定运行副本 |
| `run_instance.py` | 生成本地私有测试配置；校验、准备副本、启动指定实例 |
| `instance_session.py` | 在原生创建/提交数据之前拒绝错误房间和条件，覆盖 REST 与原生创建入口 |
| `settings.py` | 实例模式禁止读取项目 `.env`；仅显示本条件 Room 与正式/预实验配置；原单实例模式保留 |
| `project_asgi.py`、动态瓶颈创建函数 | 安装创建约束，并再次核对每个正式/预实验组的条件 |
| `DynamicSessionControls.html` | 仅显示当前实例的快捷方案，默认 PAIR-I0/I1；修复只剩一个配置时脚本提前退出的问题 |
| `scripts/verify_independent_instances.py` | 临时 PostgreSQL 集群和两个真实入口的隔离验证，自动清理自己创建的进程 |

默认每实例 40 真人：P001–P030 为 H，P031–P040 为 HA；HA 另有 10 LLM 与 10 RL。仍可使用原有预实验和流程预览配置，所有组必须与实例条件一致。两个实例各自保存 Session；对照实验仍需手动选择相同 S01–S05，不建立跨实例轮次屏障。

## 本地使用

以下命令均从项目目录执行，使用当前已有的 Python 环境。先创建一个全新的私有目录；不要复用正在运行的副本。

```sh
/opt/anaconda3/envs/otree_env/bin/python run_instance.py init-local /private/tmp/econlab-pair-20261023/pair.json --root /private/tmp/econlab-pair-20261023/instances
/opt/anaconda3/envs/otree_env/bin/python run_instance.py validate /private/tmp/econlab-pair-20261023/pair.json
/opt/anaconda3/envs/otree_env/bin/python run_instance.py prepare /private/tmp/econlab-pair-20261023/pair.json
```

然后在两个终端分别启动：

```sh
/opt/anaconda3/envs/otree_env/bin/python run_instance.py run /private/tmp/econlab-pair-20261023/pair.json i0
```

```sh
/opt/anaconda3/envs/otree_env/bin/python run_instance.py run /private/tmp/econlab-pair-20261023/pair.json i1
```

入口为 `http://127.0.0.1:8001/room/prod_room_i0` 与 `http://127.0.0.1:8002/room/prod_room_i1`。两个后台请使用独立浏览器配置文件；端口不能隔离 Cookie，同一浏览器依次登录会覆盖原来的同名 Cookie。独立签名密钥会拒绝另一个实例的管理会话，但不会阻止 Cookie 被覆盖。

生成的 `pair.json` 权限为 600，包含独立随机签名密钥、REST key、管理密码；通过本地编辑器查看和修改，不要提交或复制到聊天、日志、截图。不要让两个配置指向同一可写目录。运行副本在源项目外，复制排除 `.env`、数据库、Git、论文和历史输出；同一对副本的源码清单必须相同，修改源码或添加未登记源码后会拒绝启动，需要准备新副本。每个实例还持有自己的进程锁，重复启动在导入 oTree 和接触 journal 前被拒绝。

`init-local` 明确使用各自运行目录的 SQLite，仅供启动和界面走查；会阻断付费提供商配置继承。HA 的真实决策需要经过授权的提供商配置或测试模拟；本说明不把本地不可用 API 的回退当作正式 Agent 验收。

## PostgreSQL 配置

仓库中的 `config/instances.example.json` 仅含占位符。复制到仓库外的私有配置，权限设为 600，替换所有占位符、路径、随机密钥和两个新建测试数据库地址，再运行 validate/prepare。`production` 模式禁止 SQLite；两个 PostgreSQL 数据库可在同一服务内。额外参数只从每实例 `environment` 中显式读取，不继承原项目 `.env` 或启动终端里的数据库、Agent 密钥、超时秘密和 Python 导入路径。

如需 DeepSeek，将 `DEEPSEEK_AGENT_API_KEY`、`DEEPSEEK_AGENT_BASE_URL` 等放入对应私有配置的 `environment`。本次未配置真实 API、未付费调用。drain 继续显式为原 10 秒，不因拆实例缩短；后续需根据并发实测复核。

启动器不创建 PostgreSQL 数据库、不重置数据、不执行迁移。oTree 按原行为初始化目标库所需表。数据库 URL 校验会忽略用户名/密码差异、解码库名并拒绝同一目标；还保守要求两个 PostgreSQL 库名不同，即使主机名不同也不允许同名库，避免 DNS/IP 别名绕过。该规则同时限制了两个不同服务器使用同名库的配置，这是本次有意采用的保守策略。

## 验证证据与边界

证据目录：`output/independent_instances_20261023/`。`pg_pair_first` 完成首轮实际双入口测试；`pg_pair_final` 验证后台修复并进行真实浏览器检查；`pg_pair_locked` 在增加数据库别名拒绝和重复启动保护后再次完成真实双入口复验。浏览器截图对应未改动的最终界面。

- 新建临时 PostgreSQL 集群、两个数据库、两个实际 `run_instance → project_prodserver` 进程；每个创建 40 真人 Session。
- 观察 Web 与自己的超时子进程：实际数据库、工作目录、Agent 缓存目录一致；两个实例互不共用。超时子进程继承本实例端口与启动秘密（仅比较哈希，不写入证据日志）。
- 同样的测试 Session/参与者标识分别生成控制令牌：本实例返回 200，另一个实例返回 403；REST key 和真实后台登录 Cookie 也不能跨实例使用。此项不是统一入口、所有原生参与者 URL 碰撞的验收。
- 错误房间、顶层条件、混合组条件、预实验条件均返回 400，数据库没有新增 Session。实际创建约束不依赖隐藏前端按钮。
- PostgreSQL 排他锁使 I0 的 `/api/sessions` 持续等待时，I1 连续 20 次成功响应；另测挂起/停止 I0 后 I1 继续响应。此处的 P50/P95/max 是轻量管理查询延迟，不是参与者整轮耗时。
- I0 真正重启时，自己的未结算测试轮保留 `worker_restarted_during_round` 保护，I1 不被判为重启异常。
- 同一 I1 实例的第二个启动命令在 oTree 初始化前被拒绝，退出码 2；原实例保持正常，之后 I0 仍可正常停止并重新启动。
- 浏览器检查 I0/I1 默认 40 人、只显示本条件按钮；I1 的 HA 快捷方案改为 10 真人，预实验下仅提供 H-I1/HA-I1，并从后台成功创建无 Agent 的测试 Session。

双版本完整短回归、最终增补配置测试、Node 与补充回归的准确结果见同目录 `verification.json`；跳过项为单独启用的 80 人全 33 轮长验收。独立审查发现的后台初始化和数据库别名问题均已复现、修复并回归；复审完成，当前范围没有剩余可确认的 P1/P2 问题。
