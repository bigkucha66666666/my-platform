# 同步身份查询优化与3秒放行：本地验证

日期：2026-10-23。用户优先要求解决人数增加后重复身份查询变慢的问题，并选择新Session就绪后3秒放行。本地实现和隔离验证完成；没有连接服务器、发布或提交Git。

## 1. 主要变化

### 身份查询

原 `sync_integration.state()` 每次用本轮所有Player逐个取 `p.participant.code`，会重复加载Participant及其逐轮增长的变量。在同一HTTP请求读取7次同步状态的40席回归场景中，修前实际产生282次SELECT。

现改为只查询 `Participant.code` 一列，并通过ContextVar在同一个HTTP请求内复用不可变的code元组。键包含数据库engine身份、Session code及轮次；正常结束、异常和取消出口恢复上下文；系统超时导航有独立请求字典。oTree线程上下文复制只共享本次请求字典，不建立跨请求的全局缓存。读取失败不会缓存不完整结果。

仍返回本Session全部席位，而非只有expected_codes。因此资格集合为30人时，仍保留完整40人的原生请求故障映射，避免漏掉暂停/排除席位的迟到或失败请求。ACK、资格、异常、deadline、release和settled仍每次读取实时状态。

当前应用每轮包含同一Session全部参与者；将来若支持仅部分参与者进入该应用，应重新按该轮Player关联确定身份，不能机械复用全Session查询。

| 回归场景 | 修前 | 修后 |
| --- | ---: | ---: |
| 40席，同一HTTP请求内7次state读取 | 282次SELECT | 1次SELECT |
| 上述身份绑定阶段的Participant对象加载 | 原来逐席加载 | 0次 |
| 另一个HTTP请求 | 重复逐席加载 | 重新查询一次code，不继承上个请求缓存 |

修后还通过真实ThreadedASGI决策页GET检查：两个独立40席Session和一个单人Session，所测单次页面GET均为7次SQL执行，其中只有1次是code名单查询。这是特定夹具的计数，不是所有页面和阶段SQL总数的上限；不能与原文档不同样本的292次页面SQL直接当成受控加速比例。

身份名单查询次数现在不会随席位逐个增加，也不会随同一请求内state调用次数重复增加。但返回code、故障映射和必要的同步判定仍有随人数增长的工作量，不承诺整页时间与人数无关。

### 固定放行提前量

新Session保存：`dynamic_bottleneck_release_timing_v1 = {version: ready_lead_v1, release_lead_seconds: 3}`。

协议1和协议2均在初始化轮状态时保存提前量。正常齐员、准备期结束后的缺席处理使用同一保存值。旧Session或旧journal缺少新字段时仍按5秒解释；已有release_ts/deadline_ts不重算。重复ACK、轮状态重开与页面重入不推迟既有窗口。

3秒从本房间达到就绪条件后开始计算，不是承诺每个人离开结果页后3秒内一定可选。网络、页面处理和等候其他人就绪仍可能产生额外等待。

### 倒计时

等待页区分“等待本房间就绪”和“X秒后开始决策”。倒计时使用现有校准服务器时钟，不发放选择权限；到零后仍等待服务端确认。I1容量仍须在T到达且服务端披露后才显示。异常、截止、开始操作或确认提交时清理倒计时。

准备期限120/60秒、drain10秒、分阶段选择/结果观看时间、成本、Agent策略、排名和奖励均保留。已对照HEAD确认参数、分阶段计时、付款、排名与Agent策略源文件未改变。

## 3. 验证结果

| 验证 | 结果 |
| --- | --- |
| oTree6.0.13默认短回归 | 460项中459通过、1跳过，退出码0，约153.8秒 |
| 隔离oTree5.11.5默认短回归 | 460项中459通过、1跳过，退出码0，约153.7秒 |
| 真实HTTP新旧提前量 | I0/I1的新3秒与旧5秒均通过；ACK返回时的计划差值均约3.0000/5.0000秒 |
| 请求查询与名单覆盖 | 两个40席Session和单人；重复读取、重新请求、数据库/Session/轮次键区分；完整40席故障映射与30席资格集合分离 |
| 兼容及异常边界 | 无字段旧state/journal回退、重开不改T、提前拒绝/截止后拒绝、已渲染无ACK继续保护、I1不提前披露 |
| 前端 | 三份Node脚本全部通过，含3→2→1→服务端确认、异常停止、时钟不确定性、重试与截止 |
| 独立只读审查 | 无待修复的确认生产问题；独立6版94项、5版28项及前端脚本通过，新增HTTP夹具另经补审 |

首次默认沙箱运行未通过：6版5个失败、5版4个失败，均保留原日志。其中4个是本地127.0.0.1端口绑定被沙箱拒绝；6版另有一个测试夹具选择到资格集合外身份的错误。该夹具改为选择已就绪资格集合内身份，排除席位故障映射仍单独验证。随后在获准本地回环端口的环境完整重跑，才得到上表结果，未放宽断言或业务截止。

默认短回归跳过的1项是80人完整33轮HTTP流程，不能记成已完成。回归包含本地80人短HTTP路径与40/80回环控制请求检查；后者使用合成单线程业务负载，不是PostgreSQL ORM容量基准。本次未连接生产PostgreSQL、未做真实多设备浏览器或付费LLM并发测试，原文档中的线上长时间停留/技术异常未据此宣布全部关闭。
