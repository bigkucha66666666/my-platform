# 并行机制改进：本地修复与验收

日期：2026-10-07。针对 `fe0e228` 以及 docs 中的《统一放行协议_Player临时属性500_修复交接》和《部署与流程验收报告》进行本地修复。此次不部署、不改变正式房间或历史数据。

## 已修复的问题

1. **标准初始化后的 Decision 500。** 原实现把临时属性写入冻结的 Player，真实 GET 会在 `get_form_fields` 失败。现在用 ASGI 中间件为每次 Decision GET/POST 建立 ContextVar 字典，首次记录表单填充前是否已有选择。同步线程共享同一请求的字典，重复字段查询保留首值，请求结束或异常时清理。没有新增数据库列、关闭模型冻结或把临时标志存入 participant/session.vars。
2. **启动器漏掉 oTree 标准初始化。** `project_prodserver.py` 在应用加载前设置 `USE_TIMEOUT_WORKER=1` 并调用 `otree.main.setup()`，保留单 worker 与 timeout 子进程。`project_asgi.py` 拒绝没有初始化的直接加载，防止测试再次绕过模型约束。
3. **延迟回包延长浏览器窗口。** 原脚本从收到回包起再按旧 `server_now_ts` 计时，已过服务器截止的表单仍可能开放。现在用每页面随机 `clock_token`、请求序号与 `performance.now()`，根据请求发送/接收建立服务器时间上下界。服务器仅回显标识，POST 准入仍只使用服务器入口时间。
4. **刷新、多标签页及旧回包的边界。** oTree 会把同参与者、同页回复发给多个连接；随机页面标识阻止它们互相校时。首次非空 T/截止被保留，旧空快照不能清除 timer；技术异常一旦收到，本页停止开放和自动推进，旧正常回复不能覆盖异常状态。
5. **计划放行时重复等待回包年龄。** ARMED 回复到达后，改为按校准后的当前服务器时间下界安排 T 后请求，不再从旧回复时间重新等待。下界保证不提前探测放行信息；既避免无谓迟开，也不制造提前高频轮询。

## 保持的实验规则

- 同一 Session 的 H/HA 两组共用每轮 T 和 T+60；I0/I1 两个房间分别运行，不相互等待。刷新和重复 ACK 不重置个人 60 秒。
- I1 实际服务率仅在 T 后发送；I0 当轮决策不能获得实际值。
- 已有效保存或已自动补选的旧页面 POST 不覆盖原决定。截止前进入服务器、截止后才处理的合法 POST 仍记录 manual；真正晚到按原自动规则处理。
- 维持 3 热身+30 正式轮、标签分组、H/HA 问卷、LLM/RL 策略、成本及付费规则。技术异常不能当作普通缺席完成有效结算。

浏览器按服务器时间**上界**关闭输入，按**下界**确认已截止后再自动 POST。网络或队列的不确定区间较宽时，界面可能保守早关；不能据此宣称每台设备都完整可操作 60 秒或同一毫秒打开。服务器窗口始终为 60 秒，实际显示延迟需要单独测量。

## 验证方法与当前记录

- 新增 `dynamic_bottleneck_round/test_room_release_framework.py`。每项启动独立子进程，在临时数据库完成标准初始化，使用真实冻结 Player、HTTP 表单回调和 LiveConsumer。覆盖正常 GET、合法/非法/提前/晚到/重复/旧自动选择/排队 POST、下一轮、40/80 人、I0/I1 信息边界、HA 结算、刷新与重连。付费提供方被模拟，独立 RL 和组内结算实际运行。
- 新测试先复现冻结属性 500、缺失初始化以及延迟/跨页面/旧空回包缺陷，再修复。另覆盖同参与者并发请求隔离、线程上下文传递、异常清理和技术异常的不可逆前端停止。
- 本机 conda 环境为 oTree 6.0.13；另把服务器同版本 5.11.5 放入临时依赖目录验证，没有更换 conda 安装。
- 单房间 40 个独立真实 Chrome 上下文完成第一轮，40/40 到结果页、页面错误为 0，同一开始/截止。实际浏览器开放相对 T 的 P95 为 0.841 秒，最大 0.882 秒。这是同机本地观测，不是校园网络结果。
- 双房间 80 个真实 Chrome 上下文完成了 6 轮，两个 Session 各 240 次选择，合计 480 次均为 manual；共同 T/T+60、40 个 ACK、已结算状态一致，自动补选及技术异常为 0。I0 开放相对 T 的 P95/最大为 1.583/2.085 秒，I1 为 2.950/3.193 秒。原始报告中的 80 个 `Target ... has been closed` 是按用户要求关闭压测时产生的退出错误；退出前非关闭错误为 0。
- 用户反馈 CPU 温度高后立即终止 80 页压测，并确认本次 Chrome、19080/19001 测试服务及 timeout 子进程全部退出；没有关闭原有 Chrome。没有重新跑已完成的高负载浏览器测试。
- 最终的 ARMED 起始调度小修由 Node 延迟回包回归覆盖，未再测其真实 Chrome 时点；上述浏览器延迟不是该小修后的新测量值。80 人连续 33 轮的真实浏览器、校园网络和实际服务器数据库验收仍未完成。
- 已通过当前版本的 98 项请求/启动器/同步/入口/问卷/付费/管理员及 Room 专项 Python 回归，及 7 项 JS 脚本检查。完整动态场景回归运行 373 项，372 项通过、1 项全流程慢测试默认跳过（该项另以真实 oTree 5.11.5 显式执行并通过），耗时 48.573 秒。以上测试部分重叠，不把它们相加当作独立用例总数。
- 低负载真实 oTree 5.11.5 全流程已通过：两 Session 共 80 人完成 33 轮，2640 次选择全部 manual，每轮 H/HA 共用 T/T+60、两 Session 相互独立；80 份 H/HA 问卷、30 正式轮累计成本、现金分值及原生 Participant.payoff 均复算一致，所有参与者 finished。全程不创建 Chrome 或 TCP 服务进程。

## 测试环境与证据边界

浏览器与服务都在本机，使用临时 SQLite，真实 Chrome、页面资源及 WebSocket。HA 为 10 Human+10 模拟 LLM+10 真实 RL；模拟接口每次延迟 1.5 秒，没有实际 DeepSeek 调用。普通等待页保留原有刷新，未缩短决策窗口或付费页 60 秒结束时间。

测试脚本最初把普通等待页的取消/刷新导航当作 `ERR_ABORTED` 失败，导致工具主动关闭参与者连接。另一次并发鼠标动作卡在可见、启用、稳定后的点击阶段，尚未发出提交就导致自动补选。最终改为跨刷新持续观察转换，以各页面的原生 DOM 点击推进真实脚本与表单 POST，并记录 Decision 请求；不是直接写数据库或跳过界面逻辑。失败尝试保留，不计作通过的 80 人验收，真实自动补选也不改写成 manual。

第一次低负载全轮次检查已跑完轮次和问卷，但核对脚本误用 `Decimal(str(Currency))` 解析带单位的显示文字而失败；修正为直接读取 Currency 的数值。这是验收工具错误，没有为此修改平台付费公式。

本次原始本地证据在 `output/playwright/room_release_20261007/`；这属于临时测试产物，不随源代码提交。请求清空期 `10` 秒只是本地验收参数，不能直接作为服务器正式阈值。

当前 conda 环境运行普通回归：`python -m unittest discover -s dynamic_bottleneck_round -t .`。只在需要完整验收时运行 `RUN_ROOM_RELEASE_FULL_FLOW=1 python -m unittest dynamic_bottleneck_round.test_room_release_framework.RoomReleaseFrameworkTests.test_full_33_round_http_flow_surveys_and_cash`；不要为普通单元回归重复开浏览器/服务或并行跑多份慢测试。

10 月 7 日服务器报告已经推翻“未标准初始化 ASGI 的旧彩排足以验收”的判断。生产仍须在目标服务器、实际数据库及网络重新测量 40/80 人负载，确定清空阈值后，再切换启动命令与协议开关；本地通过不能自动推导生产已启用或已验收。
