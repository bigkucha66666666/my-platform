# 正式结果页累计排名修改与验证

## 显示规则

用户确认按“截至当前轮的累计正式成本组内排名，包含 Agent”，本轮明确不修改奖励机制。同组已完成轮数相同，因此累计成本与平均成本排序一致。

每轮正式结果页增加“你的累计排名”区域，显示本人组内名次、比较主体数、已完成正式轮数和截至本轮平均成本。比较对象为同组全部真人、LLM、RL，包括实际已结算的系统补选。H 组不会提示本组含 Agent。成本越低排名越靠前，同分并列，采用 1、1、3 的名次规则。热身不计入累计，也不显示排名。

平均成本显示四位小数；内部保留未舍入的累计成本字符串，以六位小数比较累计成本，消除浮点尾差。页面注明显示值经过四舍五入。只显示本人的名次，不公开其他主体身份、个人成绩或完整排行榜。

## 实现与兼容

- `dynamic_bottleneck_round/result_ranking.py`：纯 Decimal 累计和排名计算。
- `dynamic_bottleneck_round/__init__.py`：新建 Session 保存排名规则版本；在既有结算锁和事务内保存组累计总额以及每位真人的私有结果快照；结果页读取本人当前轮快照。
- `dynamic_bottleneck_round/Results.html`：新增排名卡片，390px 窄屏采用纵向排列；限制结果页网格宽度，保留成本图内部横向滚动，避免图表撑宽页面。
- `dynamic_bottleneck_round/test_result_ranking.py`：纯函数、快照、幂等和真实 ORM/HTTP 验证；框架测试增加独立场景入口；隔离 runner 加入新模块。

新 Session 的规则标记为 `dynamic_bottleneck_ranking_rule_v1=formal_cumulative_cost_v1`。旧 Session 保持原反馈；没有新增模型字段、不需要重置或迁移数据库。部署更新后须新建 Session 才会显示排名。

每组第一位真人的私有 vars 保存最近一次完整累计总额；每位真人自己的 vars 按原始轮号保存本人排名。下一轮必须承接紧邻上一正式轮，且主体集合完整一致。历史缺失时显示“累计排名暂不可用”，不将缺失值当零，也不阻塞原有成本/报酬结算。

结果页读取不扫描历史、不重新累加；后续轮次完成不改变历史页面名次。排名数据不写入公共反馈或 Agent 输入。新代码未改变个人成本、收益、奖金、收费和现金结算规则。
