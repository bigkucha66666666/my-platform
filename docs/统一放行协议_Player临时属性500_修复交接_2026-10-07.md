# 统一放行协议：Player 临时属性 500 修复交接

日期：2026-10-07。基于提交 `fe0e228` 和服务器 oTree 5.11.5 的真实浏览器复现。本次只提供交接，未修改业务代码。

## 问题及影响

开启 `DYNAMIC_ROOM_RELEASE_PROTOCOL=1`、配置请求清空期，并通过带入口时间戳中间件的 ASGI 服务创建新 Session 后，真人进入 Decision 页即 500：

```text
AttributeError: Player has no field "_room_release_choice_preexisting".
```

位置：`dynamic_bottleneck_round/__init__.py:4432`，`Decision.get_form_fields` 动态写入 Player。其后 `error_message`（约 4568 行）和 `before_next_page`（约 4615 行）会读取该临时属性，用来识别请求开始前已经存在的决定。

标准 `otree.main.setup()` 会初始化 ORM 并冻结模型属性；新字段不在 Player 允许属性里，因此首次 GET 的表单字段查询已经失败。40 人浏览器复现中 40/40 都失败，ACK=0，没有形成有效放行或提交。此时继续测 80 人不能证明机制有效。

## 为什么已有测试没发现

许多页面逻辑测试使用可自由添加属性的假 Player，例如 SimpleNamespace；没有在标准 ORM 初始化后让真实冻结模型经历 HTTP GET/POST。直接加载一个未完成 oTree 标准初始化的 ASGI 入口，也可能掩盖模型约束。单元回归通过不能替代该框架集成边界。

## 本地修复方向

1. 先补一个真实框架失败测试：标准 oTree 初始化、真实冻结 Player、新协议标记、实际 Decision GET。确认现有代码报上述错误，然后再修改实现。
2. 将“本请求开始前已有选择”的临时标记放入明确的请求范围存储；保留其防止 WTForms 填充覆盖旧决定的作用。不要简单删除这项判断，不要把请求临时状态随意持久化到 participant/session.vars 导致跨请求遗留。
3. 若选择 ContextVar 或视图级存储，应验证 oTree 的同步处理线程、GET/POST 和重复 `get_form_fields` 调用之间的生命周期；确保 A 参与者、B 参与者、下一轮及下一次请求不共用标记。
4. 不要通过关闭模型冻结、跳过标准初始化或给每个参与者重置个人 60 秒来规避问题。仅为临时标记新增数据库列也会引入不必要的迁移。
5. 明确部署入口的初始化责任。`project_prodserver.py` 应保留标准初始化、`USE_TIMEOUT_WORKER=1`、日志、单 worker 和超时子进程的行为；本次隔离实例由验收包装补足初始化，生产仍使用旧入口。
