## 修复方式

1. 项目启动器使用同一 Python 解释器启动 `project_timeout_worker.py`，保留原生 `otree.tasks.Worker.listen()`、任务队列和消费/事务语义，不修改 site-packages。为每次启动生成临时共享凭据；任务进程只向自身回环 HTTP origin 发送请求，每次 POST、GET 和重定向分别签名。来源校验包含请求方法、路径/查询、短期时间窗、随机 nonce 和重放检查，不信任回环 IP、User-Agent 或自报请求头。
2. 认证后的系统导航通过 ContextVar 穿过业务线程和同步回调；正常、异常、取消出口恢复上下文。系统 Decision 预访问不会启动准备时钟、登记浏览器 shell、生成控制令牌，也不进入浏览器的 pending / failed / completed / crossed 就绪证据。真实浏览器的原有 ACK、截止与技术异常保护保留。
3. 系统预访问仅展示不可操作说明，不输出 I1 当轮私有容量；真实浏览器第一次访问按原规则启动准备。真实缺席仍按既有排除/代理处理，迟到者不能取得被排除当轮的人工选择资格。补齐了迟到者在结算前提交的恢复入口，且后续自动补选仅补审计，不会再次打开已确认恢复。
4. 协议 2 动态 Session 的原生强推后端返回 409，保留原管理员鉴权与 CSRF，并在监控页明确提示。旧协议继续委托原生实现；不能借另一个 Session URL 对协议 2 的单个参与者绕过保护。
5. 未实际结算的 Results 展示等待说明，不读取空成本、不补零、不展示下一轮按钮、不启动自动推进计时；正常和原生强制超时 POST 均不能越过。实际结算完成后保留正常结果、问卷、报酬与导出。
6. 启动器正常退出或异常退栈时回收自己的超时子进程；显式 ASGI 清理仍能回收原控制线程。验收外层另创建独立自有进程组，在超时/中断/结束时回收全组，避免遗留孙测试进程继续耗 CPU；进程组回收与真实退出码有独立回归。SIGKILL 下服务需由进程管理器做整组回收，不能依赖 finally。

## 新服务器依赖统一

旧 requirements 为 `otree>=5.11,<6.0`，与本地 6.0.13 不一致。旧服务器 5.11.5 是交接中的排查记录，本次未远程复核其当前状态。

新服务器基准为 Python 3.10、oTree 6.0.13、psycopg2-binary 2.9.10，全部 15 个运行依赖在 `requirements-lock.txt` 中固定，`requirements.txt` 自动引用该约束。已在独立临时目录完成安装、逐项版本比较和不加载 conda site-packages 的导入检查；与本地现有运行依赖相比仅新增 PostgreSQL 驱动。

`Procfile` 统一到一个项目 web 启动器，由其管理一个超时子进程；不是额外再起原生 worker。完整安装、生产环境变量和旧数据库迁移边界见 [新服务器依赖与启动说明](新服务器依赖与启动说明_2026-10-19.md)。生产标志、独立密钥和管理员强认证是启动前必设项，不能把依赖安装成功当作公网安全验收。

真实超时回归使用临时 TCP 端口与临时数据库，并非直接写同步状态来代替任务链。SQLite 夹具在构造原生 Worker 后仅提交其“清理过旧测试任务”的初始化事务，避免 SQLite 单写锁阻止任务自己的 HTTP 请求；随后仍使用原生监听/消费循环。这不是 PostgreSQL 并发验收。

系统响应的最终完整 body 由回环测试父进程收集校验，不依赖服务端回调抛异常是否被服务器捕获。系统 Decision 响应不包含浏览器控制令牌、shell 令牌、容量字段或原生 Live 脚本；专门验证了 I1 直接系统 GET 和 I0 超时重定向 GET。

不能把新 oTree 直接连接唯一一份旧版本数据库。须先备份并在隔离副本验证升级及旧 Session 全轮次导出；不要执行 resetdb，不上传本地数据库，不覆盖原 .env。代码不会自动清除既有故障轮、改写历史成本、补足未完成轮次或替管理员决定故障场次如何结算。
