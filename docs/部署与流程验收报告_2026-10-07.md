## 确定断点

`dynamic_bottleneck_round/__init__.py:4432`：

```python
player._room_release_choice_preexisting = bool(preexisting)
```

在标准 oTree 初始化后，Player 被框架冻结，不允许增加未声明属性。真实错误为：

```text
AttributeError: Player has no field "_room_release_choice_preexisting".
```

调用链为 Decision GET → `has_form()` → `_get_form_fields()` → `Decision.get_form_fields()` → `Player.__setattr__`。页面没有渲染成功，浏览器无法 ACK，因此未形成放行 T 或人工决策。这个故障发生在并发提交之前，不能解释为机器资源不足或模型 API 响应慢。

按用户此前约定，本次未修改本地业务实现；修复建议、真实模型测试缺口及重验清单见《统一放行协议_Player临时属性500_修复交接_2026-10-07.md》。隔离服务显式保留 oTree 标准初始化与超时工作进程配置；不能通过跳过初始化来绕开模型保护。

## 工具错误与证据边界

- 服务器首次 Python 回归有两个失败，原因是全局 Node v10 缺少 `node:assert/strict`。使用项目隔离 Node v22 后全部通过；没有更换服务器全局 Node。
- 第一轮浏览器脚本漏勾规则说明页的阅读确认，40 人停在 Introduction，属于工具遗漏；修正后重新运行，才出现并核验 Decision 500。该遗漏没有产生决策数据。
- 只读审计工具先后修正了 oTree pickle 文本字段解码，以及单主体仍包含 `1/capacity` 瓶颈通行耗时的复算假设；修正后数据复算通过，没有修改应用或数据库记录。
- 新协议 40 人验收在同一台服务器、同一 PostgreSQL 的独立 schema 上进行，使用实际 Chrome、页面资源和 WebSocket，经校园网 SSH 隧道访问。它与正式 18000 服务隔离，但保留了标准框架初始化，足以复现确定的模型属性错误。
- 新版计时公平性、截止前进入但延迟处理的 POST、HA 真实 Agent、多房间 80 人及完整 33 轮负载仍未获得浏览器验收结论。
